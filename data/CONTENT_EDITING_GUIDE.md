# Як самостійно змінювати тексти Madeira Live Cams

Ця інструкція стосується поточної версії проєкту. Коренева папка: `C:\Users\Admin\Documents\Madeira-live-cams`. Працюйте з вихідними файлами з цієї папки, а не з `.next`: це тимчасовий результат збірки.

## 1. Де який текст

| Що змінити | Файл | Що шукати |
| --- | --- | --- |
| Звичайна картка локації й сторінка локації | `data/locations.ts` | `slug` потрібного місця; поля `summary`, `article.intro`, `article.history`, `article.highlights`, `article.practicalTip` |
| Картка ресторану | `data/restaurants.ts` | Назву або `slug` ресторану; поля `summary`, `praised`, `criticism` |
| Картка активності | `data/activities.ts` | Назву або `slug` активності; поля `summary`, `practical` |
| Початковий напис у порожній «Готовій програмі» | `pages/trip-plan.tsx` | `defaultProgram` (є український і англійський варіанти) |
| Речення у сформованій програмі: виїзд, зупинки, повернення | `pages/trip-plan.tsx` | `const programme = useMemo`, `travelLine`, `lines.push` |
| Текст про схід сонця на Pico do Arieiro **в рядку маршруту** | `pages/trip-plan.tsx` | `const sunriseSuffix` |
| Рекомендація про схід сонця **в кінці готової програми** | `pages/trip-plan.tsx` | `if (recommendations.sunrise && hasSunrise)` |
| Інші рекомендації в кінці програми | `pages/trip-plan.tsx` | `const recommendationLines = useMemo`; блоки `recommendations.weather`, `.beach`, `.levada`, `.trekking`, `.fanal`, `.lastDay`, `.food` |
| Одяг і порада залежно від температури та дощу | `pages/trip-plan.tsx` | `function adviceForWeather` |
| Текст про страви Мадейри | `pages/trip-plan.tsx` | `const madeiraFoodRecommendations` |
| Підписи розділів локації, наприклад «Історія» | `lib/i18n/uk.ts`, `lib/i18n/en.ts` | `exploreDetail` |

`data/plannerLocations.ts` об’єднує локації та ресторани для планувальника. Зазвичай текст у ньому змінювати не потрібно. `pages/explore/[slug].tsx` показує картку, але основні описи звичайних локацій бере з `data/locations.ts`.

## 2. Приклад: змінити картку Pico do Arieiro

1. Відкрийте `data/locations.ts` у VS Code.
2. Знайдіть `slug: 'pico-do-arieiro'` (зараз приблизно рядок 681). Змінюйте текст **лише всередині цього об’єкта**.
3. `summary` — короткий опис картки; `article.intro` — вступ сторінки; `article.history` — історія; `article.highlights` — пункти «Чому варто відвідати»; `article.practicalTip` — практична порада.
4. У кожному полі є `en` і `uk`. Відредагуйте обидві мови, якщо текст має збігатися за змістом. Не змінюйте `slug`, назви полів, лапки, коми й дужки.
5. Якщо в тексті потрібен апостроф, у рядку з одинарними лапками напишіть `\'` або використайте інший стиль лапок лише за умови, що код лишається коректним.

Мініприклад форми поля (це зразок, **не команда для вставлення**):

```ts
practicalTip: {
  en: 'Bring a warm jacket.',
  uk: 'Візьміть теплу куртку.'
},
```

## 3. Як змінити текст готової програми

Відкрийте `pages/trip-plan.tsx` і шукайте точну частину фрази через `Ctrl+F`.

- Текст, коли маршрут ще порожній: `defaultProgram`. Це лише підказка на екрані; сформована програма збирається нижче в `const programme = useMemo`.
- Для зупинки Pico do Arieiro із позначкою «Схід сонця» шукайте `sunriseSuffix`. Це речення додається до **рядка зупинки**.
- Окремий абзац рекомендації про одяг, їжу й туалет шукайте в `if (recommendations.sunrise && hasSunrise)`. Він з’являється в розділі «РЕКОМЕНДАЦІЇ НА ДЕНЬ», якщо відповідну рекомендацію вибрано.
- Загальні тексти готової програми знаходяться в `const programme = useMemo`: `travelLine` формує виїзд і переїзди, `lines.push` додає зупинки, посилання й повернення.
- Рекомендації для пляжу, левади, трекінгу, Фаналу й останнього дня лежать у `const recommendationLines = useMemo`. Прапорці `recommendations.*` визначають, чи показувати відповідний абзац. Умови `hasBeach`, `hasSunrise` тощо перевіряють наявність відповідних зупинок.

У цьому файлі український та англійський варіанти часто стоять поруч у виразі `locale === 'uk' ? 'український текст' : 'English text'`. Міняйте тільки потрібний текст усередині лапок, залишаючи умови й змінні. Якщо не впевнені, що весь файл лишиться коректним, зупиніться після створення резервної копії й попросіть перевірити зміну.

### Погода

Поточний планувальник бере прогноз з **Open-Meteo**, а не з OpenWeather. У `pages/trip-plan.tsx` це виклики `api.open-meteo.com` та `marine-api.open-meteo.com`. Значення температури, дощу, вітру й температури моря приходять із сервісу. Ви можете змінити навколишній текст у `recommendationLines` і пороги/поради в `adviceForWeather`, але не підміняйте числа вручну й не видаляйте вставки `${...}`. Коли прогноз недоступний, показується `weatherUnavailable` у тому ж файлі.

## 4. Безпечний порядок редагування

1. У VS Code відкрийте **папку проєкту**, а не `.next`.
2. У терміналі PowerShell перейдіть у проєкт і перевірте стан:

```powershell
Set-Location 'C:\Users\Admin\Documents\Madeira-live-cams'
git status --short --branch
git branch --show-current
```

Якщо є незнайомі незбережені зміни, спочатку розберіться з ними. Не включайте їх випадково у свій коміт. Нинішня робоча копія вже має зміну `next-env.d.ts`; ця інструкція її не змінює.

3. Створіть гілку для своєї зміни (назва має бути новою):

```powershell
git switch -c codex/edit-location-copy-2026-09-18
```

4. Перед редагуванням **кожного** цільового файлу зробіть резервну копію. Наприклад:

```powershell
Copy-Item -LiteralPath 'data\locations.ts' -Destination 'backups\locations-before-copy-edit.ts' -Force
Copy-Item -LiteralPath 'pages\trip-plan.tsx' -Destination 'backups\trip-plan-before-copy-edit.tsx' -Force
```

5. Згідно з правилами цього проєкту, файл замінюється **цілком**: підготуйте повну нову версію файлу, у VS Code виділіть увесь вміст (`Ctrl+A`), вставте її та збережіть (`Ctrl+S`). Не використовуйте автоматичне пошук/заміну фрагмента. Міняйте лише потрібні тексти, зберігаючи решту коду.
6. Перегляньте зміни й перевірте застосунок:

```powershell
git diff -- data/locations.ts pages/trip-plan.tsx
npm run lint
npx tsc --noEmit
npm run build
npm run dev
```

У браузері перевірте сторінку локації та `/trip-plan` на комп’ютері й у мобільному режимі. Для Pico додайте цю локацію, увімкніть «Схід сонця», виберіть відповідну рекомендацію й перевірте готову програму українською та англійською. `npm run dev` зупиняється клавішами `Ctrl+C`.

7. Додайте до коміту **тільки** відредаговані вихідні файли. Приклад для зміни лише картки:

```powershell
git add -- data/locations.ts
git commit -m "content: update Pico do Arieiro location copy"
```

Якщо окремо змінювали текст планувальника, зробіть окремий коміт з `git add -- pages/trip-plan.tsx` і відповідним повідомленням. Резервні копії в `backups/` не завантажуйте: папка ігнорується Git.

## 5. Як завантажити оновлення

У репозиторії налаштовано GitHub `origin`: `https://github.com/pampito89/madeira-live-cams.git`. У файлах проєкту **не вказано**, чи сайт автоматично розгортається з GitHub, яка саме гілка є виробничою та чи є окремий SSH-сервер. Тому команда `git push` точно завантажує код у GitHub, але сама по собі не гарантує оновлення сайту.

Після перевірки завантажте свою поточну гілку:

```powershell
git push -u origin (git branch --show-current)
```

Далі відкрийте GitHub і створіть Pull Request із цієї гілки до **гілки, яка підключена до виробничого розгортання**. Після об’єднання перевірте, чи система хостингу виконала нове розгортання, і відкрийте змінену сторінку на живому сайті. Не об’єднуйте в `main` навмання: у локальній копії `main` відстає від `origin/main`.

Якщо ваш сайт розгортається на **власному сервері через SSH**, потрібні реальні адреса сервера, користувач і папка застосунку. Після того як вони відомі, звичайний порядок такий (підставте свої значення):

```powershell
ssh USER@SERVER
cd /PATH/TO/madeira-live-cams
git status --short --branch
git pull --ff-only origin DEPLOY_BRANCH
npm ci
npm run build
```

Потім перезапустіть застосунок **способом, який уже налаштовано на сервері** (наприклад, через його панель керування або процес менеджер). Не запускайте довільну команду перезапуску, доки не з’ясовано назву сервісу. На сервері також не редагуйте `.next` чи окремий файл без нової збірки. Для Next.js вихідні `.ts/.tsx` збираються перед публікацією.

## 6. Якщо перевірка не пройшла

Не публікуйте зміну. Відновіть файл з копії та повторіть перевірки:

```powershell
Copy-Item -LiteralPath 'backups\locations-before-copy-edit.ts' -Destination 'data\locations.ts' -Force
Copy-Item -LiteralPath 'backups\trip-plan-before-copy-edit.tsx' -Destination 'pages\trip-plan.tsx' -Force
```

Змінюйте лише ті файли, які справді редагували. Якщо зміна вже була опублікована, відкотіть її окремим зворотним Git-комітом після перевірки впливу.
